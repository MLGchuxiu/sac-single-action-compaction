## iter6 — 新插件特性（输出契约模板 / 大观测裁剪 / 简短 recap）vs FHA

24066 出现 2 次 1800s 超时，墙钟结论不可用，只看 token/峰值/分数。

| 基准 | arm | 分 | 峰值max | 总 token | 折叠 | 备注 |
|---|---|---|---|---|---|---|
| swe | fha | 1.0 | **106.6K** | **2,250K** | 0 | 本轮 FHA 上下文冲高到 106K（接近 128K） |
| swe | n2（新模板） | 0.5 | 29.7K | 961K | 22 | 24066 超时 0 分；新模板让 recap 变长（out 2433 vs 旧 1672 tok） |
| swe | n2t4（+trim4K） | 1.0 | 49.2K | 1,110K | 26 | 24066 也超时但答对 |
| swe | n2w（+180词） | 0.5 | 25.4K | 1,020K | 26 | 24066 超时 0 分；recap out 608 tok（−63%），24213 仅 217K/7 fold（最优） |
| loong | fha | 0.50 | 51K | 227K | 0 | |
| loong | n2t4 | **0.834** | 52.7K | **223K** | 2 | legal-L2-0 得 0.667（历轮最高）；trim 有正收益 |
| loong | n2w | 0.70 | 49.7K | 262K | 2 | |
| tau2 | 各臂 | 0.5-0.76 | 8.5K | 40-52K | 0 | 无折叠，纯噪声 |

结论：
1. **新模板的“输出契约/精确值”两节会把 recap 写长**（+45% output token），净亏；必须配 `stateMaxWords` 限制。
2. **180 词限制省 summary token 显著**（608 vs 1672 tok/fold），但激进 terse 在难任务（24066）导致更多折叠/请求（19 fold/40 req）→ 超时。
3. **trimObservationOver=4000 有正收益**（Loong 分数 0.667、token 最低）。
4. 与同窗口 FHA 比：SAC 在 SWE 上 **token −50~57%、峰值 −54~76%**（106.6K → 17-49K）。
5. 端点速度波动 2-4×，超时不可归因于配置。
